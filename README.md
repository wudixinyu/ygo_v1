# 游戏王联机对战 · 服务端 + 客户端

一套简洁的游戏王联机对战系统：**服务端**（管理界面与对战服务一体）与**玩家客户端**，基于 **Godot 4.7 + GDScript** 开发。

```
┌───────────────────────────────────────────────────┐
│              游戏王服务端（一体）                    │
│  玩家服务：登录 / 大厅 / 房间 / 准备 / 对战           │
│  管理界面：玩家总览 · 房间总览 · 观战 · 广播/踢人/关房  │
│  监听端口 9000                                      │
└──────────────────────┬────────────────────────────┘
                       │ TCP（JSON 协议）
        ┌──────────────┼──────────────┐
        │              │              │
   ┌────▼────┐    ┌────▼────┐    ┌────▼────┐
   │ 客户端 1 │    │ 客户端 2 │    │ 客户端 N │   登录 → 大厅 → 建房/进房 → 准备 → 决斗
   └─────────┘    └─────────┘    └─────────┘
```

- **服务端**：一个程序搞定两件事 —— ① 为玩家提供登录、房间、**真人对战**（回合制：双方玩家轮流操作出牌——召唤 / 攻击 / 结束回合，服务端裁决并用真实 ATK/DEF 结算战斗）；② 自带管理界面，实时查看所有玩家登录、房间创建，可「进入观看」任意房间（房间界面实时镜像：玩家槽位、LP、场上怪兽/手牌/墓地真实卡图、回合、操作日志），支持广播通知、踢出玩家、强制关闭房间。内置真实卡库（`assets/cards.json` 14342 张卡片 + `assets/cards_raw` 14258 张卡图）。绑定了 3D 模型的怪兽（当前：黑魔导女孩，密码 id `38033121`）上场后，观战页会在**对应卡片格子的上方**显示 3D 怪兽模型（全息浮动效果，仅服务端观战页，客户端不受影响）。
- **客户端**：玩家端。登录服务端 → 大厅看房间列表 → 创建/加入房间 → 双方准备 → **真人操作对战**；也可观战任意房间（与服务端相同的真实卡图观战页）。**对战界面 = 上方对手场地条 + 下方我方场地**：对手条显示对方昵称 / LP / 手牌·卡组数量与场上怪兽（**拖动我方怪兽到对手条 = 攻击**：拖到对方怪兽身上打它、拖到空白处直接攻击）；我方场地含怪兽区 / 魔陷区 / 额外怪兽区、卡组 / 墓地 / 额外卡组、中央回合牌（「你的回合 / 对方回合」）、左下信息面板，**手牌在底部放大展示且支持横向滚动查看全部**、**拖动手牌怪兽到怪兽区空位 = 召唤**（拖到哪格召唤哪格，拖拽时空位绿框高亮；每回合 1 次）、**单击任意卡（含对手卡）可在左侧放大查看详情**；右侧栏为准备按钮 / 卡包选择 / **对战操作区（固定在卡包下方：操作提示 / 查看卡组 / 结束回合，等待与对战全程常驻）** 与房间动态日志，**可一键收起**（「收起/展开」按钮固定在右上角，收起后对战区自动占满全宽）；场地右侧「**卡组 / 墓地 / 额外卡组**」三个圆区均可点击 → 弹出对应列表（一行多列卡图网格）。另有与服务端同款的**卡包管理**：大厅顶栏「卡包管理」按钮 → 卡包页（预置 6 卡包 + 新建）→ 卡片管理页（搜索 / 筛选 / 排序 / 分页浏览全卡库，按卡包构筑主牌组 40 + 额外牌组 5），数据存 `user://packs.json`。

## 一、快速开始

### 方式 1：脚本一键启动（推荐）

- **`一键启动全套.bat`**：自动启动 服务端 ×1 + 客户端 ×2（客户端默认连接 127.0.0.1:9000）
- **`启动服务端.bat`**：只启动服务端（管理界面）
- **`启动客户端.bat`**：启动一个客户端（可重复双击多开）

> 脚本默认使用 `K:\Users\Godot_v4.7.2-stable_win64_console.exe`，如路径不同请用记事本修改脚本开头的 `GODOT` 变量。

### 方式 2：Godot 编辑器运行

| 项目 | 角色 | 说明 |
|---|---|---|
| `游戏王主服务` | 服务端 | 按 F5 运行，监听 9000，窗口即管理界面 |
| `游戏王客户端` | 客户端 | 按 F5 运行，登录页填服务器地址（默认 127.0.0.1:9000） |

> 注意：编辑器同一项目只能运行一个实例，客户端多开请用 bat 脚本。

## 二、测试流程

### 用两个真实客户端对战（推荐体验）

1. 启动全套（服务端 + 2 个客户端）。
2. 客户端 1：昵称填 `玩家一`，地址保持 `127.0.0.1:9000`，点「进入大厅」→ 右侧输入房间名 → 「创建房间」。
3. 客户端 2：昵称填 `玩家二`，同样登录 → 在大厅列表点该房间的「加入」。
4. 双方各自点「准备」→ 房间进入对战（随机先手）。**真人对战**：轮到你时 —— **拖动**手牌里的怪兽卡到怪兽区空位**召唤**上场（拖到哪格就召唤到哪格）、**拖动**自己的怪兽到对手条**攻击**（拖到对手怪兽身上打它；拖到空白处 = 直接攻击，仅对方场上无怪兽时）、操作完点「**结束回合**」交给对方。单击任意卡可查看详情，右栏「查看卡组」按钮或点击场地右侧「卡组 / 墓地 / 额外卡组」三个圆区可浏览对应列表（一行多列网格）。对方的操作与战果实时显示在「房间动态」。
5. 回到**服务端**界面：
   - 顶栏看到在线玩家数与房间数
   - 「玩家总览」看到两位玩家（可踢出）、「房间总览」看到房间
   - 点房间行的「进入观看」→ 弹出**观战视图**，实时镜像房间画面
   - 试试「广播通知」（客户端弹公告）、「关闭」房间

### 3D 怪兽模型（仅服务端观战页）

- **效果**：绑定了 3D 模型的怪兽（当前：黑魔导女孩，密码 id `38033121`）出现在场上时，观战页在**该卡所在卡片格子的正上方**显示 3D 模型（透明背景 + 轻微悬浮摇摆的全息效果）；卡被破坏进墓地后模型自动消失。客户端不变（不显示 3D 模型）。
- **绑定表**：`游戏王主服务\scripts\monster_model_db.gd` 的 `BINDINGS`（密码 id → 模型配置）。
- **新增一个怪兽模型**：
  1. 把 `.fbx`（或 `.glb`）放进 `游戏王主服务\assets\models\`，跑一次 Godot 导入（编辑器打开项目会自动导入；命令行可 `--headless --import`）；
  2. 在 `BINDINGS` 里加一条：`卡密码id → {"name": "显示名", "path": "res://assets/models/xxx.fbx"}`。模型背对镜头时把 `yaw` 设 `180`；大小/取景可用 `scale` / `fit` / `offset` 微调（相机自动按包围盒取景，一般不用改）。
- **快速查看效果**：启动服务端 → 两名玩家开战进入对战后，点左侧「演示：3D 怪兽上场」；或启动参数加 `--force-field=38033121`（开战时自动把该卡放上场）。

### 卡包 / 卡片管理页面（仅服务端）

- **入口**：服务端顶栏「卡包管理」→ 卡包页面；点击任意卡包进入「卡片管理」页面（编辑该卡包的牌组）。
- **卡包页面**：卡包网格（封面为卡包代表卡的**完整卡图**：等比缩放居中显示整张卡，衬暗化卡图氛围底 + 柔和投影，右上 STANDARD 标签、底部名称）；第一格「＋」新建卡包；右上「**构建全部**」为所有**还没有牌组**的卡包批量自动构筑（40 张主牌组 + 5 张额外牌组，已有牌组的卡包自动跳过）。数据存 `%APPDATA%\Godot\app_userdata\游戏王服务端\packs.json`（删除该文件可重置为预置 6 个卡包：深红力量 / 青眼MAX / Deck / 深蓝之怒 / 英雄联合 / 黑魔术爆破）。
- **卡片管理页面**：
  - 布局：左侧为**卡片详情面板**（上面卡图 / 下面详情：名称、类型、效果文本（怪兽卡含 ★等级、ATK/DEF），底部「加入牌组」「移出牌组」按钮；未选卡时提示"点击卡片查看详情"）；中间为牌组编辑区（主牌组 + 额外牌组）；右侧为卡片列表。
  - **点击卡片显示详情**（左侧面板同步展示，列表中选中的卡有金色边框高亮）；**双击卡片快速加入牌组**；**右键移出一张**；点击牌组区卡片同样打开其详情（**移出一张**请用左侧面板「移出牌组」按钮，防误删）。
  - 卡片池：预置卡包按关键词取样（如「青眼」卡包优先收青眼系），每包 80 张；新建卡包为全卡库随机 80 张。
  - 其他操作：「自动构筑」随机生成 40 张主牌组 + 5 张额外牌组；「清空」需二次确认；搜索框按卡名过滤；支持筛选（全部/怪兽/魔陷）、排序（默认/攻击/名称）、切换列数（5/4）；卡片列表**分页显示**（数据源为全卡库，每页 200 张，底部「上一页 / 页码输入框 / 总页数 / 下一页」，输入页码回车跳转；搜索/筛选/排序后回到第 1 页）。
  - 所有编辑实时保存到 `packs.json`（多实例并存时写入前自动合并磁盘数据，避免互相覆盖）。

## 四、通信协议（JSON over TCP）

帧格式：`[4 字节大端长度][UTF-8 JSON]`，消息格式 `{"type": "...", "data": {...}, "ts": 毫秒}`。

### 客户端 → 服务端

| type | 说明 |
|---|---|
| `login` / `logout` | 登录 / 登出 |
| `list_rooms` | 请求房间列表 |
| `create_room` / `join_room` / `leave_room` | 建房 / 进房 / 离房 |
| `set_ready` | 准备 / 取消准备 |
| `select_pack` | 上传对战用的卡包牌组（`{name, deck[], extra[]}`；仅等待阶段受理） |
| `duel_action` | **真人对战操作**：`summon`（召唤：`{card_id, hand_slot, pos}`，pos = 目标格 0-4，拖到哪格召唤哪格）/ `attack`（攻击：`{card_id, target}`，target = 对方怪兽 id、0 为直接攻击）/ `end_turn`（结束回合）。仅当前回合玩家、对战中受理 |
| `watch_room` / `unwatch_room` | 开始 / 停止观战 |

### 服务端 → 客户端

| type | 说明 |
|---|---|
| `login_ok` | 登录成功（返回玩家 id、昵称） |
| `room_list` / `lobby` | 大厅房间列表 |
| `room_joined` / `room_update` | 房间完整状态（玩家、LP、手牌、回合、日志、**对战状态：`active_pid` 当前回合玩家 / `summon_used` 本回合是否已召唤 / `attacked` 已攻击怪兽 id 列表**） |
| `room_closed` | 房间关闭（含原因） |
| `error` / `kicked` / `broadcast` | 错误 / 被踢出 / 广播通知 |
| `watch_snapshot` | 观战快照（每 0.5s） |
| `watch_ended` | 观战结束（房间关闭/解散时下发） |

> `watch_snapshot.room.players[]` 中每个玩家除基础字段外，还包含卡牌数据：
> `deck_count` / `deck_cards`（剩余卡组数量 / 内容）、`hand_cards`（手牌）、`field_cards`（场上怪兽，**固定 5 格、空位为 `{}`，供按格位渲染与拖放定位**）、`grave_top`（墓地最上一张），数组元素为 `{id, name, atk, def}`。观战页据此加载 `cards_raw` 中对应 id 的卡图渲染。
> 客户端内置保护：连接超时（3 秒）与登录响应超时（6 秒）检测，连错地址会给出明确提示。

## 六、常见问题

| 问题 | 解决办法 |
|---|---|
| 服务端提示"端口 9000 不可用" | 端口被占用：关闭已在运行的服务端，或改用 `--port=9001` |
| 客户端提示"连接超时，请确认服务端已启动" | 先启动服务端；确认地址与端口（默认 127.0.0.1:9000） |
